# 从建筑参考图到离线 SVG 调色工作台：完整复盘

## 最终交付

起点：一张黑底白线、建筑位于底部、顶部大面积留白的参考图。

最终交付：一张可接受的艺术性校园建筑线稿；同画面 4K RGBA PNG、11 层灰阶矢量轮廓 SVG、以及带色值/可见度/细节滑块与四种导出方式的单文件离线 HTML 工具。

## 为什么不是直接照相描边

最初的 OpenCV/Canny 自动边缘提取会把砖块噪点、反射和杂乱纹理当成重要线条，得到机械、不符合手绘风格的结果。之后尝试用 Python SVG 原生矩形、直线、多边形逐建筑画，但细节不足、造型过于简化，视觉质量仍不符合需求。

最终采用人审美选择主导的**图像生成**，把美术构图与后处理解耦：先得到看起来满意的复杂插画，之后绝不通过再生图像来改色。

## 实际渲染源

- 最终选择的 PNG：`examples/zju/source-ai-illustration.png`
- 它是 AI 图像生成模型产出的插画，**不是人工逐笔画的 SVG**。
- 源图 1672×941，黑底浅线。
- 建筑并非逐栋严格对照实景施工图描绘，不保证真实地理位置、钟楼结构或各处刻字精确。其插画风格符合用户视觉目标，但事实准确性另需审核。

## PNG 转 RGBA

1. RGB → 灰度 `Y`；
2. Alpha = `clip((Y-2)/253,0,1)`；
3. RGB 统一设为纯白，保留 Alpha 的渐变灰阶；
4. Lanczos 放大成 3840×2160（仅像素输出，不是原生新增的 4K 细节）；
5. 叠加黑色背景生成黑底版。

## RGBA 转可编辑多级轮廓 SVG

真实的矢量化发生在源灰度图上，而不是 RGB 颜色重映射之后：

1. 在原分辨率对 11 个阈值生成二值掩膜：`[6,14,26,42,62,85,112,142,174,207,237]`。
2. 二值掩膜先近邻放大 2×。
3. `cv2.findContours(...,RETR_TREE,CHAIN_APPROX_SIMPLE)` 提取封闭区域。
4. `cv2.approxPolyDP(...,epsilon=0.48,closed=True)` 减少锯齿点数。
5. 用 SVG `path d='M...Z ...'` 记录各阈值层的多子轮廓，`fill-rule='evenodd'` 处理窗洞等区域。
6. 使用逐层合成透明度 `opacity_i=(target_i-target_(i-1))/(255-target_(i-1))`，使复合后出现不同灰阶层次。

图形是一组由位图区域描出来的 SVG 路径，所以可以无位图导出并缩放，但是无法像 CAD 那样识别“每扇窗、每栋楼”的语义实体。

## HTML 工具为什么响应比较快

- 如果在拖动一个滑块时直接渲染 8MB+ SVG，浏览器 DOM 解析、绘制开销较大。
- 因此前端预览使用嵌入 PNG，在缩小的 1440×810 Canvas 上实时变化；输出 SVG 时才读取 Gzip 压缩过的原始矢量路径。
- 前端配色公式：`alpha_new=clip((alpha_old/255)^detail * intensity, 0, 1)`。
- SVG 导出用同一思路修改各矢量层的 `opacity` 与 `fill`，背景为单独的 `<rect>`。
- PNG 在 Canvas 上生成 3840×2160 的输出并通过 `toBlob` 保存。

## 用户最终截图中的参数

- `#AEB0B2`（颜色）
- `1.15×`（可见度）
- `主线突出`（细节层次模式，实际数值**未显示**）
- 预览白底。

本仓库使用 `detail=1.65` 作为这张截图视觉位置的近似初值。可以通过 UI 自由调整。

## 最终完整回归检查

- `unittest` 自动测试源代码、矢量格式、透明度、HTML 嵌入和 Skill 结构；
- 实际用示例原始 PNG 执行 4K 输出、11 层矢量化，再打包 HTML；
- Chromium/Playwright 浏览器实测加载 HTML，真正点击 SVG/PNG 导出；
- 导出后的 SVG XML 可解析，包含 11 个 `<path>` 且没有 `<image>`；
- 导出后的 PNG 尺寸 3840×2160 且空白位置 Alpha=0。

**缺点**：基于原图的轮廓自动跟踪不能让 AI 生成错误自动变正确；4K 只是再采样；即使导出 SVG 也无法还原艺术家的原始书法笔画。
